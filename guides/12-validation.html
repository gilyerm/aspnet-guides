מדריך 12: בדיקת קלט

"שדה חובה", "אימייל לא תקין": איך מוודאים שהמשתמש מילא את הטופס נכון
💡 על מה המדריך הזה? בטופס ממדריך 11 אפשר לשמור מוצר בלי שם, או במחיר של מינוס 50. במדריך הזה נגדיר כללים (שם חובה, מחיר חיובי), והאתר יבדוק אותם לבד ויציג הודעות שגיאה בעברית ליד כל שדה.

מה צריך לפני: מדריך 11 (טפסים) הוא תנאי מקדים. צריך את טופס הוספת המוצר.
📖 מושג: Validation (בדיקת קלט) בדיקה שהמידע שהמשתמש הזין הגיוני, לפני ששומרים אותו. דוגמה: בהרשמה לאתר, אם תקלידו אימייל בלי @, תקבלו הודעה "אימייל לא תקין" ולא תוכלו להמשיך. זה Validation.

1. כותבים את הכללים במודל

את הכללים כותבים ישירות על ה-Properties במודל, בתוך סוגריים מרובעים.

📖 מושג: Attribute (תגית) הערה בסוגריים מרובעים מעל קוד, שמוסיפה לו מידע או התנהגות. כבר ראינו כאלה: [HttpPost] במדריך 11. דוגמה: [Required] מעל Name אומר "השדה הזה חובה".

פתחו את Models/Product.cs. בראש הקובץ, מעל השורה namespace, הוסיפו:

using System.ComponentModel.DataAnnotations;

ואז החליפו את ה-Properties (רק את השורות שבתוך המחלקה) ב:

public int Id { get; set; }

[Required(ErrorMessage = "נא להזין שם מוצר")]
[StringLength(50, ErrorMessage = "השם יכול להיות עד 50 תווים")]
[Display(Name = "שם המוצר")]
public string Name { get; set; } = "";

[Required(ErrorMessage = "נא להזין מחיר")]
[Range(0.1, 10000, ErrorMessage = "המחיר חייב להיות בין 0.1 ל-10,000")]
[Display(Name = "מחיר")]
public decimal Price { get; set; }

[StringLength(500, ErrorMessage = "התיאור יכול להיות עד 500 תווים")]
[Display(Name = "תיאור")]
public string? Description { get; set; }

הכללים הנפוצים

Attributeמה הוא בודק
[Required]שדה חובה. אי אפשר להשאיר ריק.
[StringLength(50)]טקסט עד 50 תווים. אפשר גם מינימום: [StringLength(50, MinimumLength = 2)].
[Range(1, 100)]מספר בין 1 ל-100.
[EmailAddress]כתובת אימייל תקינה.
[Phone]מספר טלפון.
[Compare("Password")]זהה לשדה אחר (למשל "אימות סיסמה").
[Display(Name = "...")]לא בודק כלום. קובע את השם של השדה שיוצג בתווית (label).

לכל אחד מהם אפשר להוסיף ErrorMessage = "..." עם הודעה בעברית. בלי זה, ההודעה תהיה באנגלית.

2. בודקים ב-Controller

ASP.NET בודק את הכללים לבד כשהטופס מגיע, ושומר את התוצאה ב-ModelState. אנחנו רק צריכים להחליט מה לעשות אם משהו לא תקין.

ב-ProductsController, ב-Create של ה-POST, הוסיפו בהתחלה את הבדיקה:

[HttpPost]
[ValidateAntiForgeryToken]
public IActionResult Create(Product product)
{
    if (!ModelState.IsValid)
    {
        return View(product);
    }

    product.Id = products.Max(p => p.Id) + 1;
    products.Add(product);
    return RedirectToAction("Index");
}
📖 מושג: ModelState "הדוח" של הבדיקה. ModelState.IsValid הוא true אם כל הכללים עברו, ו-false אם משהו נכשל. הסימן ! פירושו "לא", אז if (!ModelState.IsValid) פירושו "אם הטופס לא תקין". אם לא תקין, מחזירים את אותו טופס עם מה שהמשתמש כבר מילא (return View(product)), כדי שלא יצטרך להקליד הכול מחדש, ועם הודעות השגיאה.

3. מציגים את ההודעות בטופס

החליפו את התוכן של Views/Products/Create.cshtml ב:

@model Product
@{
    ViewData["Title"] = "מוצר חדש";
}

<h1>הוספת מוצר</h1>

<form asp-action="Create" method="post">
    <div asp-validation-summary="ModelOnly" class="text-danger"></div>

    <div class="mb-3">
        <label asp-for="Name" class="form-label"></label>
        <input asp-for="Name" class="form-control" />
        <span asp-validation-for="Name" class="text-danger"></span>
    </div>

    <div class="mb-3">
        <label asp-for="Price" class="form-label"></label>
        <input asp-for="Price" class="form-control" />
        <span asp-validation-for="Price" class="text-danger"></span>
    </div>

    <div class="mb-3">
        <label asp-for="Description" class="form-label"></label>
        <textarea asp-for="Description" class="form-control"></textarea>
        <span asp-validation-for="Description" class="text-danger"></span>
    </div>

    <button type="submit" class="btn btn-success">שמירה</button>
    <a asp-action="Index" class="btn btn-secondary">ביטול</a>
</form>

@section Scripts {
    <partial name="_ValidationScriptsPartial" />
}
מה חדשהסבר
<span asp-validation-for="Name">המקום שבו תופיע הודעת השגיאה של השדה Name. אם אין שגיאה, הוא ריק.
<label asp-for="Name"></label>הפעם התווית ריקה, והיא לוקחת את הטקסט מה-[Display(Name = "...")] שבמודל.
asp-validation-summary="ModelOnly"מקום להודעות כלליות שלא שייכות לשדה מסוים (נשתמש בזה בהמשך).
_ValidationScriptsPartialJavaScript שבודק את הכללים כבר בדפדפן, עוד לפני שהטופס נשלח. ההודעה מופיעה מיד, בלי להמתין לשרת.
פתחו את הטופס ולחצו "שמירה" בלי למלא כלום. ליד השם והמחיר מופיעות הודעות באדום, בעברית. נסו גם מחיר 0 או 99999.

4. למה בודקים פעמיים?

הבדיקה קורית בשני מקומות: בדפדפן (בזכות _ValidationScriptsPartial) ובשרת (בזכות ModelState.IsValid).

  • בדפדפן: נוח למשתמש. ההודעה מופיעה מיד.
  • בשרת: בשביל הביטחון. משתמש שמבין קצת יכול לכבות את ה-JavaScript או לשלוח בקשה בלי הטופס בכלל. לכן אסור לוותר על הבדיקה ב-Controller.

🔧 אם זה לא עובד

  • קו אדום מתחת ל-[Required]: חסרה השורה using System.ComponentModel.DataAnnotations; בראש המודל.
  • המוצר נשמר למרות שהשדות ריקים: חסרה הבדיקה if (!ModelState.IsValid) ב-Controller.
  • ההודעות מופיעות רק אחרי שליחה, ולא מיד: חסר ה-@section Scripts עם _ValidationScriptsPartial בסוף ה-View.
  • חלק מההודעות באנגלית: לכל Attribute צריך ErrorMessage משלו. הודעה כמו "The field ... must be a number" מופיעה כשמקלידים אותיות בשדה של מספר.

✏️ תרגיל

  1. הוסיפו כללים לתכונה Stock (אם הוספתם אותה): חובה, בין 0 ל-1000, עם הודעות בעברית.
  2. בטופס "צור קשר" (מהתרגיל במדריך 11): השם חובה ובין 2 ל-30 תווים, האימייל חובה ותקין, וההודעה חובה ועד 1000 תווים.

📌 מה למדנו

  • את הכללים כותבים במודל, עם Attributes כמו [Required], [Range] ו-[StringLength], וכל אחד עם ErrorMessage בעברית.
  • ב-Controller בודקים ModelState.IsValid, ואם לא תקין מחזירים את הטופס.
  • ב-View מוסיפים asp-validation-for ליד כל שדה, ו-_ValidationScriptsPartial לבדיקה מיידית בדפדפן.
