מדריך 11: טפסים

ממלאים טופס בדפדפן, והמידע מגיע לשרת
💡 על מה המדריך הזה? עד עכשיו המידע זרם בכיוון אחד: מהשרת לדפדפן. בטופס זה הפוך: המשתמש מקליד משהו, לוחץ "שמירה", והמידע נשלח לשרת. נבנה טופס להוספת מוצר חדש.

מה צריך לפני: מדריך 10 (מודלים) הוא תנאי מקדים. צריך את המודל Product ואת ProductsController עם רשימת המוצרים.

🌐 צריכים לרענן את הבסיס? ב-יסודות HTML, סעיף הטפסים יש הסבר קצר ודוגמאות שאפשר לשנות ולראות את התוצאה מיד.

1. GET ו-POST

📖 מושג: GET ו-POST שני סוגים של בקשות שהדפדפן שולח לשרת. GET אומר "תביא לי עמוד" (קישור, הקלדת כתובת). POST אומר "הנה מידע, תעשה איתו משהו" (שליחת טופס). דוגמה: כשנכנסים לעמוד "הוספת מוצר", הדפדפן שולח GET ומקבל טופס ריק. כשלוחצים "שמירה", הדפדפן שולח POST עם מה שהקלדתם.

לכן לטופס יש שני Actions באותו שם:

נכנסים לעמודGET ‏/Products/Create
←
Action 1מחזיר טופס ריק
←
ממלאים ולוחצים "שמירה"POST ‏/Products/Create
←
Action 2מקבל את המוצר ושומר

2. ה-Actions ב-Controller

ב-ProductsController, הוסיפו (בתוך המחלקה, אחרי ה-Actions הקיימים):

// GET: מציג טופס ריק
public IActionResult Create()
{
    return View();
}

// POST: מקבל את מה שהמשתמש מילא
[HttpPost]
[ValidateAntiForgeryToken]
public IActionResult Create(Product product)
{
    product.Id = products.Max(p => p.Id) + 1;
    products.Add(product);
    return RedirectToAction("Index");
}
מההסבר
// ...הערה. C# מתעלמת ממנה, היא רק בשבילנו.
[HttpPost]"ה-Action הזה מטפל רק בבקשות POST", כלומר רק בשליחת הטופס. בלי זה, לא היה ברור איזה מה-Create לבחור.
[ValidateAntiForgeryToken]הגנה: מוודא שהטופס נשלח מהאתר שלכם, ולא מאתר זדוני שמנסה לשלוח בשמכם. תמיד שמים את זה על POST.
Create(Product product)הקסם: ASP.NET לוקח את השדות שמילאו בטופס, ובונה מהם אובייקט Product מוכן.
products.Max(p => p.Id) + 1נותנים למוצר החדש מספר: הגבוה ביותר ברשימה, ועוד 1.
RedirectToAction("Index")אחרי השמירה, שולחים את המשתמש לרשימת המוצרים.
📖 למה Redirect ולא סתם return View? אחרי שליחת טופס, אם המשתמש ירענן את העמוד, הדפדפן ישלח את הטופס שוב, והמוצר יתווסף פעמיים. RedirectToAction מעביר את הדפדפן לעמוד חדש (בבקשת GET), ואז רענון פשוט טוען שוב את הרשימה.

3. הטופס

קליק ימני על Create (הראשון, בלי ה-[HttpPost]) ← Add View ← Razor View - Empty ← שם Create.cshtml. החליפו את התוכן ב:

@model Product
@{
    ViewData["Title"] = "מוצר חדש";
}

<h1>הוספת מוצר</h1>

<form asp-action="Create" method="post">
    <div class="mb-3">
        <label asp-for="Name" class="form-label">שם המוצר</label>
        <input asp-for="Name" class="form-control" />
    </div>

    <div class="mb-3">
        <label asp-for="Price" class="form-label">מחיר</label>
        <input asp-for="Price" class="form-control" />
    </div>

    <div class="mb-3">
        <label asp-for="Description" class="form-label">תיאור</label>
        <textarea asp-for="Description" class="form-control"></textarea>
    </div>

    <button type="submit" class="btn btn-success">שמירה</button>
    <a asp-action="Index" class="btn btn-secondary">ביטול</a>
</form>
📖 מושג: asp-for מחבר שדה בטופס ל-Property במודל. asp-for="Name" אומר "השדה הזה הוא ה-Name של המוצר". כך ASP.NET יודע לבנות את ה-Product כשהטופס מגיע לשרת. דוגמה: <input asp-for="Price" /> הופך בדפדפן ל-<input name="Price" ... />. כשהטופס נשלח, הערך של השדה Price נכנס ל-product.Price.

ולבסוף, כפתור שמוביל לטופס. בראש Views/Products/Index.cshtml, מתחת ל-<h1>, הוסיפו:

<a asp-action="Create" class="btn btn-primary mb-3">הוספת מוצר</a>
היכנסו ל-/Products, לחצו "הוספת מוצר", מלאו את הטופס ולחצו "שמירה". חזרתם לרשימה, והמוצר החדש מופיע בה!

4. מציצים מאחורי הקלעים

בעמוד הטופס, לחצו בדפדפן Ctrl+U ומצאו את ה-<form>. תראו:

  • לכל שדה יש name="Name", name="Price" וכו'. זה מה ש-asp-for יצר.
  • יש שדה נסתר בשם __RequestVerificationToken עם קוד ארוך. זו ההגנה שה-[ValidateAntiForgeryToken] בודק. הטופס הוסיף אותה לבד.
⚠️ שימו לב: כרגע אפשר לשמור מוצר בלי שם, או עם מחיר שלילי. במדריך 12 (בדיקת קלט) נלמד לחסום את זה, ולהציג הודעות שגיאה בעברית.

🔧 אם זה לא עובד

  • המוצר נשמר, אבל השם או המחיר ריקים: הערך ב-asp-for לא זהה לשם ה-Property במודל. בדקו אותיות גדולות וקטנות: Name ולא name.
  • שגיאה 400 (Bad Request) אחרי לחיצה על "שמירה": חסר שדה ההגנה. ודאו שה-<form> כתוב עם asp-action (ולא action רגיל), כי רק אז השדה נוסף לבד.
  • לחיצה על "שמירה" לא עושה כלום, או מגיעה ל-404: בדקו שהכפתור הוא type="submit" ונמצא בתוך ה-<form>, ושיש Action עם [HttpPost].
  • "Sequence contains no elements": הרשימה ריקה, ואין מה לחשב ממנו Max. ודאו שיש לפחות מוצר אחד ברשימה ההתחלתית.

✏️ תרגיל

  1. אם הוספתם במדריך 10 את התכונה Stock (מלאי), הוסיפו לה שדה בטופס.
  2. בנו טופס "צור קשר" חדש: מודל ContactMessage עם שם, אימייל והודעה, Controller ששומר את ההודעות ברשימה static, ועמוד שמציג את כל ההודעות שהתקבלו.

📌 מה למדנו

  • לטופס יש שני Actions באותו שם: אחד מציג אותו (GET), ואחד עם [HttpPost] מקבל אותו.
  • asp-for מחבר כל שדה ל-Property במודל, ו-ASP.NET בונה מהטופס אובייקט מוכן.
  • על כל POST שמים [ValidateAntiForgeryToken], והטופס מוסיף את ההגנה לבד.
  • אחרי שמירה עושים RedirectToAction, כדי שרענון לא ישלח את הטופס שוב.
