מדריך 15: הכול בלחיצת כפתור

Scaffolding: עמודי הצגה, הוספה, עריכה ומחיקה שנוצרים לבד
💡 על מה המדריך הזה? במדריכים 10 עד 14 כתבנו ביד Controller ועמודים להצגה ולהוספה של מוצרים. זה חשוב כדי להבין איך זה עובד. אבל Visual Studio יודעת ליצור את כל זה לבד, כולל עריכה ומחיקה, בלחיצת כפתור. בפרויקט אמיתי זה חוסך שעות.

מה צריך לפני: מדריך 13 (מסד נתונים) הוא תנאי מקדים: צריך מודל שיש לו DbSet ב-ApplicationDbContext, וטבלה במסד הנתונים. בדוגמה נשתמש ב-Category ממדריך 14, אבל זה עובד עם כל מודל.
📖 מושג: Scaffolding (פיגומים) יצירה אוטומטית של קוד: Visual Studio מסתכלת על המודל, ויוצרת Controller וחמישה עמודים מוכנים. השם בא מפיגומים של בניין: מבנה זמני שמקימים מהר, ואחר כך מתאימים ומשפרים. ככה גם כאן: מקבלים עמודים שעובדים, ואז משנים אותם לפי הטעם.
📖 מושג: CRUD ראשי תיבות של ארבע הפעולות הבסיסיות על מידע: Create (הוספה), Read (הצגה), Update (עריכה), Delete (מחיקה). Scaffolding יוצר את כל הארבע.

1. יוצרים Controller עם עמודים

  • עצרו את האתר, ולחצו Ctrl+Shift+B (Build). ודאו שאין שגיאות ב-Error List. Scaffolding לא יעבוד אם יש שגיאות בקוד.
  • ב-Solution Explorer, קליק ימני על Controllers ← Add ← New Scaffolded Item.
  • בצד, בחרו MVC, ובמרכז בחרו MVC Controller with views, using Entity Framework. לחצו Add.
  • בחלון שנפתח:
    • Model class: בחרו Category.
    • DbContext class: בחרו ApplicationDbContext.
    • השאירו מסומנים את Generate views, Reference script libraries ו-Use a layout page.
    • Controller name: יופיע CategoriesController. השאירו אותו.
  • לחצו Add. בפעם הראשונה Visual Studio עשויה להתקין חבילות NuGet. זה לוקח קצת זמן, חכו בסבלנות.
כאן תבוא תמונה של חלון Add MVC Controller with views, using Entity Framework, עם השדות ממולאים
נוצרו: הקובץ Controllers/CategoriesController.cs, והתיקייה Views/Categories עם חמישה קבצים: Index, Details, Create, Edit, Delete.

3. קוראים את הקוד שנוצר

פתחו את CategoriesController.cs. רוב הקוד דומה למה שכתבנו בעצמנו במדריכים 11 ו-13, עם כמה תוספות:

מה רואיםמה זה
async, await, Task<IActionResult>, ToListAsync()גרסה "אסינכרונית" של אותו קוד: בזמן שהשרת מחכה למסד הנתונים, הוא יכול לטפל בבקשות של משתמשים אחרים. זה תקין, אל תיבהלו. מבחינתנו, זה עושה בדיוק אותו דבר כמו ToList().
int? id ו-if (id == null) return NotFound();בדיקה שבכתובת באמת יש מספר. אם מישהו נכנס ל-/Categories/Edit בלי מספר, הוא יקבל 404 במקום שגיאה.
[Bind("Id,Name")]הגנה: רק השדות האלה יילקחו מהטופס. גם אם מישהו "מוסיף" לטופס שדה אחר, הוא לא ייכנס.
DeleteConfirmedהמחיקה בשני שלבים: עמוד Delete (GET) שואל "בטוחים?", ורק לחיצה על הכפתור שם (POST) באמת מוחקת.
_context.Update(category)שמירת שינויים בעריכה. כמו Add, אבל לשורה שכבר קיימת.

4. מתאימים את העמודים

העמודים שנוצרו באנגלית ובסגנון בסיסי. הם קבצי cshtml רגילים, ואפשר לשנות בהם הכול:

  • תרגום: בכל אחד מחמשת הקבצים ב-Views/Categories, החליפו את הטקסטים באנגלית. לדוגמה: Create New ← הוספת קטגוריה, Edit ← עריכה, Details ← פרטים, Delete ← מחיקה, Back to List ← חזרה לרשימה, Save ← שמירה, Create ← הוספה, Are you sure you want to delete this? ← בטוחים שרוצים למחוק?. גם הכותרות (<h1>) ו-ViewData["Title"].
  • שמות העמודות: הכותרות בטבלה מגיעות מה-[Display(Name = "...")] שבמודל. אם הוספתם אותו במדריכים 12 ו-14, הן כבר בעברית.
  • עיצוב: אפשר להוסיף קלאסים של Bootstrap (מדריך 9). למשל, להפוך את הקישורים לכפתורים: class="btn btn-sm btn-primary".
  • קישור בתפריט: הוסיפו ב-_Layout.cshtml קישור עם asp-controller="Categories" asp-action="Index" (מדריך 6).

5. Scaffolding למודל עם קשר

אם עושים Scaffolding למודל שיש בו מפתח זר (כמו Product עם CategoryId), Visual Studio יוצרת רשימה נפתחת לבד. יש רק דבר אחד לתקן: ברשימה יופיעו מספרים (Id) במקום שמות.

ב-Controller שנוצר, חפשו שורות כאלה (הן מופיעות בכמה Actions):

ViewData["CategoryId"] = new SelectList(_context.Categories, "Id", "Id");

ושנו בכל אחת את ה-"Id" השני ל-"Name":

ViewData["CategoryId"] = new SelectList(_context.Categories, "Id", "Name");
⚠️ כבר יש לכם ProductsController? Scaffolding לא יכול ליצור Controller בשם שכבר קיים. אם תרצו לנסות על מוצרים, תנו שם אחר (למשל ProductsAdminController, כעמודי ניהול), או מחקו קודם את הישן.
⚠️ חשוב לפני שמעלים את האתר: כרגע כל אחד יכול להוסיף, לערוך ולמחוק. במדריך 17 (עבודה עם משתמשים) נלמד לחסום את העמודים האלה, כך שרק מנהל יוכל להיכנס אליהם.

🔧 אם זה לא עובד

  • "There was an error running the selected code generator": הסיבה הנפוצה היא שגיאות בקוד. עשו Build (Ctrl+Shift+B) ותקנו את כל השגיאות. ודאו שהאתר לא רץ.
  • שגיאה על גרסאות של חבילות: ב-Manage NuGet Packages, בלשונית Installed, ודאו שכל החבילות שמתחילות ב-Microsoft.EntityFrameworkCore וב-Microsoft.VisualStudio.Web.CodeGeneration באותה גרסה ראשית כמו ה-.NET (למשל 10.x.x).
  • המודל לא מופיע ברשימה של Model class: עשו Build ונסו שוב.
  • "Invalid object name 'Categories'" כשנכנסים לעמוד: אין טבלה. הוספתם DbSet, אבל לא הרצתם Add-Migration ו-Update-Database (מדריך 13).
