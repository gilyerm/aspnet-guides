מדריך 17: עבודה עם משתמשים

עמודים למחוברים בלבד, המשתמש המחובר, ותפקיד "מנהל"
💡 על מה המדריך הזה? מערכת ההרשמה וההתחברות כבר קיימת באתר מהיום הראשון (בזכות Individual Accounts במדריך 1). עכשיו נשתמש בה: נחסום עמודים למי שלא מחובר, נציג מידע לפי המשתמש, וניצור תפקיד "מנהל" שרק לו מותר לנהל את האתר.

מה צריך לפני: פרויקט עם Individual Accounts (מדריך 1), ומסד נתונים שכבר נוצר, כלומר נרשמתם לפחות פעם אחת (מדריך 2, סעיף 7). לדוגמאות כדאי שיהיו לכם ProductsController (מדריכים 10-13) ו-CategoriesController (מדריך 15), אבל זה עובד עם כל Controller.

1. שני מושגים שנשמעים דומה

📖 Authentication (אימות זהות) "מי אתה?". ההתחברות עם אימייל וסיסמה. אחרי התחברות, האתר יודע מי המשתמש.
📖 Authorization (הרשאה) "מה מותר לך?". גם אחרי שהאתר יודע מי אתם, לא בטוח שמותר לכם להיכנס לכל עמוד. דוגמה: בבית הספר, כרטיס התלמיד מוכיח מי אתם (Authentication). אבל לחדר המורים מותר להיכנס רק למורים (Authorization).

2. עמודים למחוברים בלבד: [Authorize]

כדי לחסום עמוד למי שלא מחובר, שמים מעליו [Authorize]. לדוגמה, רק משתמש מחובר יוכל להוסיף מוצר. ב-ProductsController, הוסיפו מעל שני ה-Create:

[Authorize]
public IActionResult Create()
{
    ...
}

[HttpPost]
[ValidateAntiForgeryToken]
[Authorize]
public IActionResult Create(Product product)
{
    ...
}

(ה-... הוא הקוד שכבר יש לכם בפנים, אל תמחקו אותו.) Authorize יסומן באדום. Ctrl+. יוסיף using Microsoft.AspNetCore.Authorization;.

התנתקו מהאתר (Logout) ונסו להיכנס ל-/Products/Create. האתר שולח אתכם לעמוד ההתחברות. אחרי שתתחברו, תחזרו אוטומטית לטופס.
💡 על כל ה-Controller בבת אחת: אפשר לשים [Authorize] מעל השורה public class ...Controller, ואז כל העמודים בו חסומים. אם רוצים שעמוד אחד בכל זאת יהיה פתוח לכולם, שמים מעליו [AllowAnonymous].

3. מי מחובר עכשיו?

בכל View אפשר לבדוק אם המשתמש מחובר, ולהציג את השם שלו, דרך User:

@if (User.Identity?.IsAuthenticated == true)
{
    <p>שלום, @User.Identity.Name! 👋</p>
}
else
{
    <p>
        שלום אורח!
        <a asp-area="Identity" asp-page="/Account/Login">התחברו</a>
        או
        <a asp-area="Identity" asp-page="/Account/Register">הירשמו</a>
    </p>
}
מההסבר
User.Identity?.IsAuthenticatedtrue אם מישהו מחובר.
User.Identity.Nameשם המשתמש. כברירת מחדל זה האימייל שאיתו נרשם.
asp-area="Identity" asp-page="..."עמודי ההרשמה וההתחברות לא נמצאים ב-Controller רגיל, אלא באזור מיוחד בשם Identity. לכן הקישור אליהם קצת שונה.

ב-Controller, המזהה (Id) של המשתמש המחובר מתקבל כך. הוא שימושי כשרוצים לשמור "מי יצר את זה", למשל להזמנות של כל משתמש:

var userId = User.FindFirstValue(ClaimTypes.NameIdentifier);

(Ctrl+. יוסיף using System.Security.Claims;. דוגמה מלאה של "רק הנתונים שלי" תמצאו בספריית קטעי הקוד.)

4. תפקיד "מנהל"

📖 מושג: Role (תפקיד) קבוצה של משתמשים עם אותן הרשאות. נותנים למשתמש תפקיד, ואז חוסמים עמודים לפי תפקיד, ולא לפי כל משתמש בנפרד. דוגמה: תפקיד Admin (מנהל). רק מי שיש לו את התפקיד הזה יוכל להיכנס לעמודי הניהול.

שלב א: מפעילים תפקידים

פתחו את Program.cs וחפשו את השורה שמתחילה ב-builder.Services.AddDefaultIdentity. היא נראית בערך כך:

builder.Services.AddDefaultIdentity<IdentityUser>(options => options.SignIn.RequireConfirmedAccount = true)
    .AddEntityFrameworkStores<ApplicationDbContext>();

הוסיפו לפני .AddEntityFrameworkStores את השורה .AddRoles<IdentityRole>():

builder.Services.AddDefaultIdentity<IdentityUser>(options => options.SignIn.RequireConfirmedAccount = true)
    .AddRoles<IdentityRole>()
    .AddEntityFrameworkStores<ApplicationDbContext>();

שלב ב: יוצרים את המנהל הראשון

בעיה: רק מנהל יכול לתת תפקיד מנהל, אבל עוד אין אף מנהל. הפתרון: קוד שרץ כשהאתר עולה, ונותן תפקיד מנהל לאימייל מסוים.

  • הירשמו לאתר (Register) עם האימייל שאתם רוצים שיהיה המנהל, ואשרו את החשבון בקישור Click here to confirm your account.
  • ב-Program.cs, מצאו את השורה var app = builder.Build();, והדביקו מיד אחריה: 
    using (var scope = app.Services.CreateScope())
{
    var roleManager = scope.ServiceProvider.GetRequiredService<RoleManager<IdentityRole>>();
    var userManager = scope.ServiceProvider.GetRequiredService<UserManager<IdentityUser>>();

    // יוצרים את התפקיד Admin, אם הוא עוד לא קיים
    if (!await roleManager.RoleExistsAsync("Admin"))
    {
        await roleManager.CreateAsync(new IdentityRole("Admin"));
    }

    // נותנים תפקיד Admin למשתמש עם האימייל הזה
    var adminEmail = "admin@example.com";
    var admin = await userManager.FindByEmailAsync(adminEmail);
    if (admin != null && !await userManager.IsInRoleAsync(admin, "Admin"))
    {
        await userManager.AddToRoleAsync(admin, "Admin");
    }
}

    החליפו את admin@example.com באימייל שאיתו נרשמתם.

  • הריצו את האתר. אם הייתם מחוברים, התנתקו והתחברו מחדש (התפקיד נטען רק בהתחברות).
💡 מה הקוד עושה? בכל הפעלה של האתר הוא בודק: האם יש תפקיד Admin? אם לא, יוצר. האם המשתמש עם האימייל הזה קיים, ועוד אין לו את התפקיד? אם כן, נותן לו. בהפעלות הבאות הוא רואה שהכול כבר קיים, ולא עושה כלום. await פירושו "חכה שהפעולה במסד הנתונים תסתיים" (ראינו אותו ב-Scaffolding, מדריך 15).
💡 עוד מנהלים: אפשר לשכפל את שלוש השורות האחרונות (מ-var adminEmail) עם אימייל אחר.

שלב ג: חוסמים עמודים למנהלים בלבד

כותבים את התפקיד בתוך ה-[Authorize]. לדוגמה, כל עמודי ניהול הקטגוריות ממדריך 15. ב-CategoriesController.cs, מעל השורה public class CategoriesController : Controller:

[Authorize(Roles = "Admin")]
  • מחוברים כמנהל: /Categories עובד כרגיל.
  • מחוברים כמשתמש רגיל (הירשמו עם אימייל אחר): מופיע עמוד Access denied.
  • לא מחוברים: מועברים לעמוד ההתחברות.

5. כפתורים וקישורים שרק מנהל רואה

ב-View, User.IsInRole("Admin") בודק אם המשתמש המחובר הוא מנהל. לדוגמה, קישור לניהול הקטגוריות בתפריט (_Layout.cshtml), שמופיע רק למנהל:

@if (User.IsInRole("Admin"))
{
    <li class="nav-item">
        <a class="nav-link text-dark" asp-controller="Categories" asp-action="Index">ניהול קטגוריות</a>
    </li>
}
⚠️ להסתיר כפתור זה לא להגן על העמוד! גם אם הכפתור לא מופיע, מישהו יכול להקליד את הכתובת ישירות בדפדפן. ההגנה האמיתית היא [Authorize(Roles = "Admin")] ב-Controller. הסתרת הכפתור היא רק בשביל הנוחות. תמיד עושים את שניהם.

🔧 אם זה לא עובד

  • נתתם תפקיד מנהל, אבל עדיין מקבלים Access denied: התנתקו והתחברו מחדש. בדקו גם שהאימייל בקוד כתוב בדיוק כמו שנרשמתם.
  • "No service for type RoleManager": שכחתם את .AddRoles<IdentityRole>() ב-Program.cs (שלב א).
  • קווים אדומים על await ב-Program.cs: ודאו שהדבקתם את הקוד אחרי var app = builder.Build();, ולא בתוך פונקציה אחרת.
  • [Authorize] לא חוסם כלום: בדקו שהוא מעל ה-Action או ה-Controller הנכון, ושלא שמתם בטעות [AllowAnonymous].
  • האתר קורס מיד בהפעלה, עם שגיאה על מסד הנתונים (למשל "Cannot open database"): הקוד שיוצר את המנהל רץ בהפעלה, ומסד הנתונים עוד לא קיים. הריצו Update-Database ב-Package Manager Console, והפעילו שוב.
  • במחשב אחר המשתמש לא מנהל: מסד הנתונים שם חדש וריק (מדריך 13). הירשמו שם עם אותו אימייל, והקוד ייתן לו את התפקיד בהפעלה הבאה.

✏️ תרגיל

  1. אפשרו להוסיף מוצרים (Create) רק למנהלים, והציגו את הכפתור "הוספת מוצר" ברשימה רק למנהלים.
  2. הוסיפו לדף הבית ברכה אישית: "שלום, [אימייל]" למחוברים, ו"שלום אורח" עם קישור להרשמה לאחרים.
  3. צרו עמוד "האזור האישי" (Profile) שרק משתמשים מחוברים יכולים להיכנס אליו, והציגו בו את האימייל ואת ה-Id של המשתמש.

📌 מה למדנו

  • [Authorize] חוסם עמוד למי שלא מחובר, ו-[Authorize(Roles = "Admin")] חוסם למי שאינו מנהל.
  • ב-View: User.Identity.IsAuthenticated, User.Identity.Name ו-User.IsInRole("Admin").
  • תפקידים מפעילים עם .AddRoles<IdentityRole>(), ואת המנהל הראשון יוצרים בקוד ב-Program.cs.
  • אחרי שינוי תפקיד צריך להתנתק ולהתחבר מחדש. ולהסתיר כפתור לא מחליף את [Authorize].
