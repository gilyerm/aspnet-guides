מדריך 13: מסד נתונים

טבלה משלכם במסד הנתונים: המידע נשמר גם אחרי שסוגרים את האתר
💡 על מה המדריך הזה? במדריכים 10 ו-11 המוצרים נשמרו ברשימה בזיכרון, ונעלמו בכל פעם שעצרנו את האתר. עכשיו נשמור אותם במסד הנתונים, באותו מקום שבו כבר נשמרים המשתמשים של האתר.

מה צריך לפני: מדריך 10 (מודלים) הוא תנאי מקדים: צריך את המודל Product. אם עשיתם גם את מדריכים 11 ו-12, הטופס ימשיך לעבוד. מומלץ גם להכיר את Package Manager Console ואת SQL Server Object Explorer ממדריך 2.

1. שלושה מושגים

📖 DbContext המחלקה שמחברת את הקוד שלנו למסד הנתונים. בפרויקט שלכם כבר יש אחת, בשם ApplicationDbContext, בתיקייה Data. דרכה נוצרו טבלאות המשתמשים.
📖 DbSet שורה ב-DbContext שאומרת "תיצור טבלה לסוג הזה". כל DbSet הוא טבלה אחת. דוגמה: public DbSet<Product> Products { get; set; } פירושו "צור טבלה בשם Products, שכל שורה בה היא Product".
📖 Migration קובץ עם "הוראות בנייה" למסד הנתונים: אילו טבלאות ועמודות להוסיף או לשנות. בכל פעם שמשנים מודל, יוצרים Migration חדש ומריצים אותו. דוגמה: כמו הוראות הרכבה של רהיט מאיקאה. Add-Migration כותב את ההוראות, ו-Update-Database מרכיב לפיהן.

2. מכינים את המודל

מסד הנתונים צריך לדעת כמה ספרות לשמור למחיר. ב-Models/Product.cs:

  • בראש הקובץ הוסיפו: 
    using System.ComponentModel.DataAnnotations.Schema;
  • מעל השורה public decimal Price { get; set; } הוסיפו: 
    [Column(TypeName = "decimal(10,2)")]
    זה אומר: עד 10 ספרות, מתוכן 2 אחרי הנקודה (אגורות).

3. מוסיפים DbSet

פתחו את Data/ApplicationDbContext.cs. המחלקה שם עוד ריקה, והיא נראית כך:

public class ApplicationDbContext(DbContextOptions<ApplicationDbContext> options) : IdentityDbContext(options)
{
}
💡 מה זה הסוגריים אחרי שם המחלקה? זו דרך מקוצרת לכתוב "המחלקה מקבלת הגדרות חיבור למסד הנתונים". לא צריך להבין אותה, ולא נוגעים בשורה הזאת. עובדים רק בין הסוגריים המסולסלים.
  • בין הסוגריים המסולסלים ({ ו-}), הוסיפו: 
    public DbSet<Product> Products { get; set; }
  • אם Product מסומן באדום: עמדו עליו, Ctrl+., ובחרו את ה-using.

הקובץ ייראה כך:

public class ApplicationDbContext(DbContextOptions<ApplicationDbContext> options) : IdentityDbContext(options)
{
    public DbSet<Product> Products { get; set; }
}

(בפרויקטים שנוצרו בגרסאות ישנות יותר, בתוך המחלקה יש פונקציה שמתחילה ב-public ApplicationDbContext(. גם זה בסדר: מוסיפים את ה-DbSet מתחתיה, בתוך המחלקה.)

4. Migration: יוצרים את הטבלה

  • עצרו את האתר אם הוא רץ.
  • פתחו את Package Manager Console: Tools ← NuGet Package Manager ← Package Manager Console.
  • הקלידו ולחצו Enter: 
    Add-Migration AddProducts
    AddProducts הוא שם שאתם בוחרים, שמתאר את השינוי (באנגלית, בלי רווחים). חכו שתופיע ההודעה To undo this action, use Remove-Migration. בתיקייה Data/Migrations נוצר קובץ חדש עם השם שבחרתם.
  • עכשיו הקלידו ולחצו Enter: 
    Update-Database
    חכו להודעה Done.
פתחו את SQL Server Object Explorer (מדריך 2, סעיף 7), לחצו על כפתור הרענון (🔄), ופתחו את Tables של מסד הנתונים. יש טבלה חדשה: dbo.Products, עם עמודות Id, Name, Price ו-Description.
⚠️ שני כללי ברזל:
  • לא מוחקים את התיקייה Migrations ולא קבצים בתוכה. מסד הנתונים "זוכר" אילו Migrations כבר רצו, ומחיקה תשבש את הכול.
  • לא משנים את מבנה הטבלאות ידנית ב-SQL Server Object Explorer. כל שינוי במבנה עובר דרך המודל ו-Migration.

5. ה-Controller עובד עם מסד הנתונים

עכשיו נחליף את הרשימה שבזיכרון במסד הנתונים. פתחו את ProductsController.cs, והחליפו את כל מה שבתוך המחלקה (מהסוגר המסולסל אחרי public class ProductsController : Controller ועד הסוגר שסוגר אותה) ב:

private readonly ApplicationDbContext _context;

public ProductsController(ApplicationDbContext context)
{
    _context = context;
}

public IActionResult Index()
{
    var products = _context.Products.ToList();
    return View(products);
}

public IActionResult Details(int id)
{
    var product = _context.Products.Find(id);
    if (product == null)
    {
        return NotFound();
    }
    return View(product);
}

public IActionResult Create()
{
    return View();
}

[HttpPost]
[ValidateAntiForgeryToken]
public IActionResult Create(Product product)
{
    if (!ModelState.IsValid)
    {
        return View(product);
    }

    _context.Products.Add(product);
    _context.SaveChanges();
    return RedirectToAction("Index");
}

ApplicationDbContext יסומן באדום. Ctrl+. יוסיף בראש הקובץ using MyProject.Data;.

מההסבר
_contextהחיבור למסד הנתונים. מעכשיו, כל עבודה עם המוצרים עוברת דרכו.
public ProductsController(ApplicationDbContext context)בנאי (Constructor): פונקציה שרצה כשה-Controller נוצר. ASP.NET "מגיש" לה את החיבור למסד הנתונים, ואנחנו שומרים אותו ב-_context. לא צריך להבין לעומק, רק להעתיק.
_context.Products.ToList()"תביא את כל השורות מטבלת Products, כרשימה".
_context.Products.Find(id)"תביא את המוצר שה-Id שלו הוא id".
_context.Products.Add(product)"תכין את המוצר הזה להוספה".
_context.SaveChanges()"עכשיו תשמור באמת". בלי השורה הזאת, שום דבר לא נכתב למסד הנתונים!
💡 ומה עם ה-Id? שימו לב שהשורה product.Id = products.Max(...) + 1 נעלמה. מסד הנתונים נותן לכל שורה חדשה Id בעצמו (1, 2, 3...).
הריצו ונכנסו ל-/Products. הרשימה ריקה (המוצרים הישנים היו רק בזיכרון). הוסיפו שני מוצרים בטופס. עכשיו עצרו את האתר והריצו שוב: המוצרים עדיין שם! אפשר לראות אותם גם ב-SQL Server Object Explorer, בקליק ימני על dbo.Products ← View Data.

6. שינוי מודל בהמשך

כל פעם שמשנים מודל שיש לו טבלה (מוסיפים Property, מוחקים, משנים סוג), חוזרים על אותם שני צעדים:

1. משניםאת המודל
←
2. Add-Migrationעם שם חדש שמתאר את השינוי
←
3. Update-Databaseמעדכן את הטבלה

לדוגמה, אחרי שמוסיפים ל-Product את public int Stock { get; set; }:

Add-Migration AddProductStock
Update-Database

(מקלידים כל שורה בנפרד, ולוחצים Enter אחרי כל אחת.) לכל Migration צריך שם אחר.

⚠️ זכרו: מסד הנתונים נמצא על המחשב, לא בפרויקט. במחשב אחר (אחרי Clone או העתקה) מריצים Update-Database, וכל הטבלאות נוצרות שם. הן יהיו ריקות: הנתונים עצמם לא עוברים. ראו מדריך 3, סעיף 4.

🔧 אם זה לא עובד

  • "Invalid object name 'Products'": הטבלה לא קיימת במסד הנתונים. שכחתם להריץ Update-Database.
  • "The model for context 'ApplicationDbContext' has pending changes": שיניתם מודל, אבל לא יצרתם לו Migration. הריצו קודם Add-Migration עם שם חדש, ורק אחר כך Update-Database.
  • "Build failed": יש שגיאות בקוד. הפקודות לא ירוצו עד שתתקנו אותן (פתחו את Error List).
  • "The process cannot access the file" או שהפקודה נתקעת: האתר עדיין רץ. עצרו אותו ונסו שוב.
  • "The term 'Add-Migration' is not recognized": חסרה החבילה Microsoft.EntityFrameworkCore.Tools. התקינו אותה ב-NuGet (מדריך 2, סעיף 6), עם גרסה שמתאימה לגרסת ה-.NET.
  • הנתונים לא נשמרים: חסר _context.SaveChanges(); אחרי ה-Add.
  • טעיתם ב-Migration ועוד לא הרצתם Update-Database: Remove-Migration מוחק את ה-Migration האחרון בצורה בטוחה.

✏️ תרגיל

  1. הוסיפו ל-Product את Stock (אם עוד לא הוספתם), צרו Migration והריצו אותו. בדקו ב-SQL Server Object Explorer שנוספה עמודה.
  2. הוסיפו שדה למלאי בטופס, הוסיפו מוצר, ובדקו שהמלאי נשמר.
  3. בונוס: העבירו גם את טופס "צור קשר" (מתרגיל 11) למסד הנתונים: DbSet, Migration, ושינוי ה-Controller.

📌 מה למדנו

  • טבלה חדשה = DbSet ב-ApplicationDbContext, ואז Add-Migration ו-Update-Database.
  • כל שינוי במודל = Migration חדש. לא מוחקים את תיקיית Migrations.
  • ב-Controller: ToList() מביא הכול, Find(id) מביא אחד, Add ואחריו SaveChanges() שומר.
  • מסד הנתונים נמצא ב-LocalDB על המחשב. במחשב אחר מריצים Update-Database.
