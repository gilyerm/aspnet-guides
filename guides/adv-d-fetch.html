מתקדם ד: JS שמדבר עם השרת

כפתור "אהבתי" שמתעדכן בלי לטעון את העמוד מחדש, עם fetch
💡 על מה המדריך הזה? עד עכשיו, כל פעולה (שליחת טופס, לחיצה על קישור) טענה עמוד שלם מחדש. באתרים מודרניים, הרבה דברים קורים "בשקט": לוחצים לייק, והמספר עולה מיד. כאן נבנה כפתור "אהבתי" כזה: JavaScript שולח בקשה לשרת, מקבל תשובה, ומעדכן רק את המספר.

מה צריך לפני: מדריך 13 (מסד נתונים) הוא תנאי מקדים. צריך גם להכיר JavaScript בעמוד (מדריך 8).
📖 מושג: JSON פורמט טקסט פשוט להעברת מידע בין השרת ל-JavaScript. נראה כמו אובייקט של JavaScript. דוגמה: { "likes": 7 }. השרת יחזיר את זה במקום עמוד HTML שלם.
📖 מושג: fetch פונקציה של JavaScript ששולחת בקשה לשרת מתוך העמוד, בלי לעבור לעמוד אחר. התשובה חוזרת ל-JavaScript, והוא מחליט מה לעשות איתה.

1. מונה לייקים במודל

  • ב-Models/Product.cs, הוסיפו: 
    public int Likes { get; set; }
  • עצרו את האתר, וב-Package Manager Console (כל שורה בנפרד): 
    Add-Migration AddProductLikes
Update-Database

2. Action שמחזיר JSON

ב-ProductsController, הוסיפו:

[HttpPost]
[ValidateAntiForgeryToken]
public IActionResult Like(int id)
{
    var product = _context.Products.Find(id);
    if (product == null)
    {
        return NotFound();
    }

    product.Likes++;
    _context.SaveChanges();

    return Json(new { likes = product.Likes });
}
מההסבר
product.Likes++מעלה את המונה ב-1.
return Json(...)במקום View, מחזירים JSON. הדפדפן יקבל {"likes":8}.
new { likes = ... }אובייקט "על המקום", בלי מחלקה. נוח כשרק מחזירים כמה ערכים.
[HttpPost] ו-[ValidateAntiForgeryToken]הפעולה משנה מידע, אז היא POST ומוגנת, כמו טופס (מדריך 11).

3. הכפתור בעמוד

ב-Views/Products/Index.cshtml:

  • בראש העמוד (אחרי ה-<h1>) הוסיפו את שדה ההגנה. ה-JavaScript ייקח ממנו את הקוד ויצרף אותו לבקשה: 
    @Html.AntiForgeryToken()
  • ליד כל מוצר (בתוך הלולאה, למשל בעמודה חדשה בטבלה) הוסיפו כפתור: 
    <button type="button" class="btn btn-sm btn-outline-danger like-btn" data-id="@product.Id">
    ❤️ <span class="count">@product.Likes</span>
</button>
    data-id שומר על הכפתור את ה-Id של המוצר, כדי שה-JavaScript ידע על איזה מוצר לחצו.
  • בסוף הקובץ: 
    @section Scripts {
    <script src="~/js/likes.js" asp-append-version="true"></script>
}

4. ה-JavaScript

צרו את הקובץ wwwroot/js/likes.js (קליק ימני על wwwroot/js ← Add ← New Item ← JavaScript File):

document.querySelectorAll(".like-btn").forEach(function (btn) {
    btn.addEventListener("click", async function () {
        const id = btn.dataset.id;
        const token = document.querySelector('input[name="__RequestVerificationToken"]').value;

        const response = await fetch("/Products/Like/" + id, {
            method: "POST",
            headers: { "RequestVerificationToken": token }
        });

        if (response.ok) {
            const data = await response.json();
            btn.querySelector(".count").textContent = data.likes;
        }
    });
});
שורההסבר
querySelectorAll(".like-btn").forEachעובר על כל כפתורי הלייק בעמוד, ומחבר לכל אחד פעולה בלחיצה.
btn.dataset.idקורא את ה-data-id מהכפתור.
tokenהקוד משדה ההגנה (@Html.AntiForgeryToken()). שולחים אותו בכותרת בשם RequestVerificationToken, וכך [ValidateAntiForgeryToken] מוצא אותו.
await fetch(...)שולח בקשת POST ל-/Products/Like/5, ומחכה לתשובה. await עובד רק בתוך פונקציה עם async.
response.oktrue אם השרת הצליח.
await response.json()הופך את ה-JSON שחזר לאובייקט: data.likes.
.textContent = data.likesמעדכן רק את המספר על הכפתור. שאר העמוד לא זז.
לחצו על ❤️ ליד מוצר. המספר עולה מיד, בלי שהעמוד נטען מחדש. רעננו את העמוד: המספר נשאר, כי הוא שמור במסד הנתונים.

5. רואים את הבקשה בעיניים

בדפדפן, F12 ← לשונית Network. לחצו על לייק. תופיע שורה חדשה, Like/5 (או מספר אחר). לחצו עליה, ובלשונית Response תראו את ה-JSON שהשרת החזיר.

🔧 אם זה לא עובד

  • לחיצה לא עושה כלום: F12 ← Console. "Cannot read properties of null (reading 'value')" אומר שחסר @Html.AntiForgeryToken() בעמוד.
  • ב-Network רואים 400: שדה ההגנה לא נשלח, או שהשם של הכותרת לא בדיוק RequestVerificationToken.
  • ב-Network רואים 404: הכתובת ב-fetch לא נכונה. בדקו את שם ה-Controller וה-Action.
  • המספר עולה, אבל אחרי רענון חוזר: חסר _context.SaveChanges();.

✏️ תרגיל

  1. אחרי לחיצה, הפכו את הכפתור ל"מלא" (btn-danger במקום btn-outline-danger). רמז: btn.classList.replace(...).
  2. מיינו את רשימת המוצרים לפי מספר הלייקים, מהגבוה לנמוך (מתקדם ב).
  3. בונוס: אפשרו לייק רק למשתמשים מחוברים ([Authorize], מדריך 17). מה מחזיר השרת למי שלא מחובר? בדקו ב-Network.

📌 מה למדנו

  • Action יכול להחזיר JSON עם return Json(...), במקום עמוד.
  • fetch שולח בקשה מתוך JavaScript, ו-await response.json() קורא את התשובה.
  • גם בקשות מ-JavaScript שמשנות מידע צריכות POST ושדה הגנה.
  • F12 ← Network מראה כל בקשה ואת התשובה שלה.
