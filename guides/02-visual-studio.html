מדריך 2: עבודה ב-Visual Studio

הכרת המסך, הרצת האתר, קיצורים שימושיים וצפייה במסד הנתונים
💡 על מה המדריך הזה? Visual Studio היא התוכנה שבה נכתוב את כל האתר. בהתחלה יש בה המון כפתורים וחלונות, אבל בפועל משתמשים כל הזמן רק בחלק קטן מהם. במדריך הזה נכיר את החלק הזה.

מה צריך לפני: פרויקט שיצרתם במדריך 1.
📖 מושג: סביבת פיתוח (IDE) תוכנה שמרכזת במקום אחד את כל מה שצריך כדי לכתוב תוכנה: עורך קוד, כפתור הרצה, הודעות שגיאה ועוד. דוגמה: Visual Studio היא סביבת פיתוח. Word הוא "סביבת עבודה" למסמכים, ו-Visual Studio היא סביבת עבודה לקוד.

2. הרצה ועצירה של האתר

📖 מושג: localhost כשמריצים את האתר, הוא לא עולה לאינטרנט. הוא רץ רק על המחשב שלכם, ולכן הכתובת בדפדפן מתחילה ב-localhost, שפירושו "המחשב הזה". המספר שאחרי הנקודתיים נקרא פורט, והוא נבחר אוטומטית. דוגמה: https://localhost:7123/. אם תשלחו את הכתובת הזאת לחבר, היא לא תעבוד אצלו, כי אצלו "המחשב הזה" הוא המחשב שלו.

יש שתי דרכים להריץ את האתר:

דרךאיךמתי משתמשים
הרצה עם דיבאגכפתור ה-Play הירוק, או F5כשרוצים לעצור את הקוד באמצע ולבדוק מה קורה בו (נלמד במדריך הדיבאג).
הרצה בלי דיבאגCtrl+F5כשרק רוצים לראות את האתר. עולה מהר יותר.
📖 מושג: דיבאג (Debug) מצב הרצה מיוחד שבו Visual Studio "מסתכלת" על הקוד בזמן שהוא רץ, ויכולה לעצור אותו בשורה שתבחרו. דוגמה: כמו לעצור סרטון בסצנה מסוימת כדי לראות מה קורה בה בדיוק.

עצירת האתר: לוחצים על הריבוע האדום בסרגל הכלים, או Shift+F5. אם הרצתם בלי דיבאג, פשוט סוגרים את החלון השחור (הקונסולה) שנפתח.

כאן תבוא תמונה של סרגל הכלים: כפתור Play, כפתור העצירה וכפתור Hot Reload
הריצו את האתר עם Ctrl+F5, ובדקו שהכתובת בדפדפן מתחילה ב-https://localhost. אחר כך עצרו אותו.
⚠️ חשוב: לפני שמתקינים חבילה (NuGet) או מריצים פקודה של מסד הנתונים, עוצרים את האתר. אחרת תקבלו שגיאה שהקובץ "נעול" (בשימוש).

3. Hot Reload: לראות שינויים בלי להריץ מחדש

כשהאתר רץ ואתם משנים משהו בקוד, אין צורך לעצור ולהריץ מחדש. אפשר:

  • לשמור את הקובץ (Ctrl+S) וללחוץ על כפתור Hot Reload (סמל של להבה 🔥) בסרגל הכלים.
  • או להפעיל עדכון אוטומטי: לחצו על החץ הקטן שליד כפתור הלהבה, וסמנו Hot Reload on File Save. מעכשיו כל שמירה תעדכן את האתר לבד.
  • חזרו לדפדפן ורעננו את העמוד (F5 בדפדפן).
⚠️ שימו לב: Hot Reload לא מצליח בכל שינוי. אם השינוי לא מופיע, או שקפצה הודעה שאי אפשר להחיל אותו, פשוט עוצרים את האתר ומריצים מחדש.

4. Visual Studio עוזרת לכם לכתוב

השלמה אוטומטית (IntelliSense)

כשמתחילים להקליד, נפתחת רשימה של הצעות. בוחרים עם החיצים ולוחצים Tab או Enter. אם הרשימה לא נפתחה, אפשר לפתוח אותה עם Ctrl+Space.

הנורה הצהובה (תיקון מהיר)

כשמופיע קו אדום מתחת לקוד, עומדים עליו ולוחצים Ctrl+. (קונטרול ונקודה). Visual Studio תציע תיקונים, ולפעמים התיקון הוא בדיוק מה שצריך.

📖 מושג: using שורה בראש קובץ C# שאומרת "אני הולך להשתמש בדברים מהספרייה הזאת". בלעדיה, C# לא מכירה את השמות מהספרייה. דוגמה: כתבתם List<string> וקיבלתם קו אדום? Ctrl+. יציע להוסיף using System.Collections.Generic; בראש הקובץ.

6. התקנת חבילות NuGet

📖 מושג: חבילה (NuGet) קוד מוכן שמישהו אחר כתב, ואפשר להוסיף לפרויקט בלחיצה, במקום לכתוב הכול לבד. NuGet היא "החנות" שממנה מתקינים חבילות. דוגמה: כמו אפליקציה שמתקינים בטלפון. במדריכים הבאים נתקין חבילות למשל כדי ליצור עמודים אוטומטית.
  • עצרו את האתר אם הוא רץ.
  • ב-Solution Explorer, לחצו קליק ימני על שם הפרויקט (השורה המודגשת, לא השורה העליונה של ה-Solution) ובחרו Manage NuGet Packages.
  • עברו ללשונית Browse והקלידו את שם החבילה שהמדריך אומר לכם.
  • בחרו את החבילה מהרשימה. מצד ימין, ב-Version, ודאו שהגרסה מתחילה באותו מספר כמו גרסת ה-.NET של הפרויקט (למשל 10.x.x לפרויקט ב-.NET 10).
  • לחצו Install ואשרו את החלונות שקופצים (OK, ואחר כך I Accept אם מופיע).
כאן תבוא תמונה של חלון NuGet, עם סימון של Browse, Version ו-Install
עברו ללשונית Installed באותו חלון. החבילה שהתקנתם אמורה להופיע ברשימה.

Package Manager Console

חלון שבו כותבים פקודות לפרויקט. נשתמש בו בעיקר במדריך מסד הנתונים. פותחים אותו מהתפריט: Tools ← NuGet Package Manager ← Package Manager Console. החלון נפתח בתחתית המסך, ושם מקלידים פקודה ולוחצים Enter.

7. צפייה במידע שבמסד הנתונים

📖 מושג: מסד נתונים (Database) המקום שבו האתר שומר מידע לאורך זמן, כמו משתמשים שנרשמו. המידע מסודר בטבלאות, כמו בגיליון אקסל: כל שורה היא פריט אחד, וכל עמודה היא פרט עליו. דוגמה: בטבלת המשתמשים, כל שורה היא משתמש אחד, ויש עמודות כמו אימייל ושם משתמש.
⚠️ איפה מסד הנתונים נמצא? הוא לא נמצא בתיקיית הפרויקט, אלא בתוכנה בשם LocalDB שמותקנת על המחשב עצמו. לכן אם תעבירו את הפרויקט למחשב אחר, מסד הנתונים לא יעבור איתו (במדריך 3 נראה מה עושים במקרה כזה).

שלב א: יצירת מסד הנתונים (פעם אחת)

מסד הנתונים לא קיים עד שיוצרים אותו בפעם הראשונה. הדרך הכי פשוטה:

  • הריצו את האתר ולחצו על Register בתפריט העליון. הזינו אימייל וסיסמה ולחצו Register.
  • בפעם הראשונה יופיע דף שגיאה שכתוב בו שפעולה על מסד הנתונים נכשלה. זה תקין! בדף יש כפתור כחול Apply Migrations. לחצו עליו.
  • כשמופיעה הודעה שהפעולה הצליחה, רעננו את העמוד (F5 בדפדפן). אם הדפדפן שואל אם לשלוח שוב את הטופס, אשרו.
  • יופיע עמוד שמבקש לאשר את החשבון. מכיוון שהאתר לא באמת שולח מיילים, יש בעמוד קישור Click here to confirm your account. לחצו עליו, ואחר כך תוכלו להתחבר עם Login.
כאן תבוא תמונה של דף השגיאה עם הכפתור Apply Migrations

שלב ב: פתיחת הטבלאות ב-Visual Studio

  • בתפריט העליון בחרו View ← SQL Server Object Explorer.
  • בחלון שנפתח, פתחו (לחיצה על החץ הקטן): SQL Server ← (localdb)\MSSQLLocalDB ← Databases.
  • מצאו את מסד הנתונים של הפרויקט. השם שלו מתחיל ב-aspnet- ואחריו שם הפרויקט. פתחו אותו, ואז את התיקייה Tables.
  • לחצו קליק ימני על הטבלה dbo.AspNetUsers ובחרו View Data.
כאן תבוא תמונה של SQL Server Object Explorer עם העץ פתוח עד הטבלה
נפתחה טבלה, ובה שורה עם האימייל שנרשמתם איתו. זה המשתמש שלכם, שמור במסד הנתונים!
⚠️ כלל ברזל: מותר להסתכל על הנתונים, ואפילו לשנות או למחוק שורות. אבל לא משנים כאן את מבנה הטבלאות (עמודות). את המבנה קובע קוד ה-C# שלכם, ושינוי כאן ישבור את האתר.

🔧 אם זה לא עובד

  • כפתור ה-Play אפור ולא לוחץ: האתר כנראה עדיין רץ. עצרו אותו (Shift+F5) ונסו שוב.
  • "The process cannot access the file... because it is being used": האתר רץ בזמן שניסיתם להתקין חבילה או לבנות. עצרו אותו ונסו שוב.
  • לא מוצאים את מסד הנתונים ב-SQL Server Object Explorer: כנראה עוד לא יצרתם אותו. חזרו לשלב א. אם כבר יצרתם, לחצו על כפתור הרענון (🔄) בראש החלון.
  • חלון נעלם: Window ← Reset Window Layout.

✏️ תרגיל

  1. הירשמו לאתר עם משתמש נוסף (אימייל אחר).
  2. פתחו שוב את הטבלה dbo.AspNetUsers ובדקו שיש בה עכשיו שתי שורות. אם לא רואים את החדשה, לחצו על כפתור הרענון בחלון הטבלה.
  3. מצאו בטבלה את העמודה שבה שמורה הסיסמה. האם רואים בה את הסיסמה שהקלדתם? (רמז: לא, והסיבה טובה. האתר שומר סיסמאות בצורה מוצפנת כדי שאף אחד לא יוכל לקרוא אותן.)

📌 מה למדנו

  • החלונות החשובים: Solution Explorer, העורך, Error List ו-Output. אם משהו התבלגן: Reset Window Layout.
  • מריצים עם F5 או Ctrl+F5, ועוצרים עם Shift+F5. האתר רץ על localhost, כלומר רק על המחשב שלכם.
  • מתקינים חבילות דרך Manage NuGet Packages, ותמיד עוצרים את האתר לפני.
  • מסד הנתונים נמצא ב-LocalDB על המחשב, ורואים אותו ב-SQL Server Object Explorer.
