מדריך 3: Git ו-GitHub

שומרים גיבוי של הפרויקט בענן, ועוברים בין מחשבים, הכול בכפתורים של Visual Studio
💡 למה צריך את זה? פרויקט שנמצא רק על מחשב אחד יכול להיעלם: המחשב מתקלקל, מישהו מוחק תיקייה, או שאתם פשוט רוצים להמשיך לעבוד בבית על מה שהתחלתם בבית הספר. GitHub שומר עותק של הפרויקט באינטרנט, וגם זוכר כל גרסה ששמרתם, כך שתמיד אפשר לחזור אחורה.

מה צריך לפני: פרויקט שיצרתם במדריך 1, וחשבון ב-GitHub (ההרשמה בחינם).

המושגים שצריך להכיר

יש כאן כמה מילים חדשות. אל דאגה, אחרי פעם-פעמיים זה נהיה טבעי:

📖 Git ו-GitHub Git היא תוכנה שעוקבת אחרי השינויים בקבצים של הפרויקט וזוכרת כל גרסה. GitHub הוא אתר שבו שומרים את הפרויקט יחד עם כל הגרסאות שלו. דוגמה: Git הוא כמו "היסטוריית גרסאות" של מסמך ב-Google Docs, ו-GitHub הוא כמו Google Drive שבו המסמך שמור.
📖 Repository (מאגר) "התיקייה" של הפרויקט ב-GitHub. לכל פרויקט יש מאגר משלו.
📖 Commit שמירת "נקודת שמירה" של הפרויקט על המחשב שלכם, עם משפט קצר שמתאר מה עשיתם. דוגמה: כמו נקודת שמירה במשחק מחשב. אם משהו נשבר אחר כך, אפשר לחזור אליה.
📖 Push ו-Pull Push (דחיפה) מעלה את נקודות השמירה מהמחשב שלכם ל-GitHub. Pull (משיכה) מוריד מ-GitHub את מה שחדש שם למחשב שלכם. דוגמה: עשיתם Commit בבית הספר ו-Push. בבית עושים Pull, ומקבלים בדיוק את מה שעשיתם בבית הספר.
📖 Clone הורדת פרויקט מ-GitHub למחשב שעוד אין בו את הפרויקט. עושים את זה פעם אחת בכל מחשב חדש.
⚠️ הכי חשוב לזכור: Commit שומר רק על המחשב שלכם! הגיבוי ב-GitHub מתעדכן רק אחרי Push.

1. חיבור Visual Studio לחשבון GitHub (פעם אחת)

  • ב-Visual Studio, בתפריט העליון בחרו File ← Account Settings.
  • תחת All Accounts לחצו Add ובחרו GitHub.
  • ייפתח דפדפן. התחברו לחשבון GitHub שלכם ואשרו את הגישה (Authorize).
  • חזרו ל-Visual Studio. החשבון אמור להופיע ברשימה.
כאן תבוא תמונה של חלון Account Settings עם הכפתור Add

2. העלאת הפרויקט ל-GitHub (פעם אחת לכל פרויקט)

  • פתחו את הפרויקט ב-Visual Studio.
  • בתפריט העליון בחרו Git ← Create Git Repository.
  • בצד ימין של החלון ודאו שנבחר GitHub, ובחרו את החשבון שלכם ב-Account.
  • ב-Repository name כתבו שם למאגר (באנגלית, בלי רווחים). אפשר להשאיר את השם שמופיע, שזה שם הפרויקט.
  • תיבת הסימון Private repository קובעת מי יכול לראות את הפרויקט. מסומנת: רק אתם (ומי שתזמינו). לא מסומנת: כולם. אם אתם לא בטוחים, שאלו את המורה.
  • לחצו Create and Push.
כאן תבוא תמונה של חלון Create Git Repository עם סימון של השדות
היכנסו ל-github.com, לחצו על תמונת הפרופיל ובחרו Your repositories. המאגר החדש אמור להופיע, ובתוכו התיקיות של הפרויקט (Controllers, Views ועוד).
📖 קובץ ‎.gitignore רשימה של קבצים ש-Git לא מעלה. Visual Studio יוצרת אותה לבד. בזכותה תיקיות כמו bin ו-obj (קבצים זמניים שנוצרים מחדש בכל הרצה) לא נכנסות לגיבוי.

3. העבודה היומיומית: Commit ו-Push

את זה עושים בכל פעם שמסיימים לעבוד, או אחרי שמשהו מתחיל לעבוד ורוצים לשמור אותו:

  • פתחו את החלון Git Changes: בתפריט View ← Git Changes (או Ctrl+0 ואז Ctrl+G). בחלון מופיעה רשימת הקבצים ששיניתם.
  • בתיבה שבראש החלון כתבו משפט קצר שמתאר מה עשיתם.
  • לחצו על החץ הקטן שליד הכפתור Commit All, ובחרו Commit All and Push. כך עושים Commit ו-Push בלחיצה אחת.
כאן תבוא תמונה של חלון Git Changes: תיבת ההודעה והכפתור Commit All עם החץ

אם כבר לחצתם Commit All בלבד, אפשר לעשות Push בנפרד: בראש החלון Git Changes יש חץ שמצביע למעלה (↑). לחיצה עליו היא Push.

🔁 תזכורת קבועה: סיימתם לעבוד? Commit ו-Push לפני שסוגרים את Visual Studio. ככה העבודה שלכם שמורה ב-GitHub, ותוכלו להמשיך ממנה מכל מחשב.

4. מעבר בין מחשבים

במחשב שעוד אין בו את הפרויקט: Clone (פעם אחת)

  • ב-github.com, פתחו את המאגר שלכם. לחצו על הכפתור הירוק Code והעתיקו את הכתובת שמופיעה (מתחילה ב-https://github.com/).
  • פתחו את Visual Studio. במסך הפתיחה בחרו Clone a repository.
  • ב-Repository location הדביקו את הכתובת. ב-Path בחרו איפה לשמור את הפרויקט במחשב.
  • לחצו Clone. הפרויקט יורד ונפתח.
⚠️ מסד הנתונים לא עובר עם הפרויקט! הוא שמור ב-LocalDB על המחשב הקודם (ראו מדריך 2). במחשב החדש צריך ליצור אותו מחדש: פתחו Tools ← NuGet Package Manager ← Package Manager Console, הקלידו את הפקודה הבאה ולחצו Enter: 
Update-Database
מסד הנתונים ייווצר עם כל הטבלאות, אבל ריק. המשתמשים והנתונים שהזנתם במחשב הקודם נשארים שם.
⚠️ אותה גרסת .NET בכל מחשב: אם יצרתם את הפרויקט ב-.NET 10 בבית הספר, גם במחשב בבית צריך להיות מותקן .NET 10 (הוא מגיע עם Visual Studio מעודכנת). אחרת הפרויקט לא ייפתח או לא ירוץ.

במחשב שכבר יש בו את הפרויקט: Pull בתחילת כל עבודה

  • פתחו את הפרויקט ואת החלון Git Changes.
  • לחצו על החץ שמצביע למטה (↓) בראש החלון. זה Pull: הוא מוריד את מה שעשיתם במחשב האחר.
  • עכשיו אפשר לעבוד. בסוף, כרגיל: Commit All and Push.
💡 הכלל לזכור: מתחילים לעבוד ← Pull. מסיימים לעבוד ← Commit ו-Push.

5. מה לא מעלים ל-GitHub

אם המאגר ציבורי, כל אחד בעולם יכול לקרוא את הקוד. לכן לעולם לא כותבים בקוד סיסמאות אמיתיות, מפתחות של שירותים (API Keys) או פרטים אישיים. גם במאגר פרטי זה הרגל טוב.

🔧 אם זה לא עובד

  • Push נכשל עם הודעה שיש שינויים שאין לכם (rejected): כנראה עבדתם במחשב אחר ולא עשיתם Pull. לחצו Pull (↓), ואחר כך שוב Push (↑).
  • הודעה על Conflict (התנגשות): אותו קובץ שונה בשני מחשבים שונים, ו-Git לא יודע איזו גרסה לשמור. אל תלחצו על שום דבר באקראי, וקראו למורה.
  • אין תפריט Git בסרגל העליון: כנראה גרסה ישנה של Visual Studio. עדכנו אותה דרך Help ← Check for Updates.
  • אחרי Clone, האתר נותן שגיאה של מסד נתונים: שכחתם להריץ Update-Database (ראו סעיף 4).

✏️ תרגיל

  1. שנו את הכותרת בדף הבית של האתר (בקובץ Views/Home/Index.cshtml) למשהו משלכם.
  2. עשו Commit All and Push עם הודעה שמתארת את השינוי.
  3. היכנסו למאגר ב-github.com, לחצו על הקישור Commits (מעל רשימת הקבצים), ומצאו את ההודעה שכתבתם.

📌 מה למדנו

  • Commit שומר נקודת שמירה במחשב, Push מעלה אותה ל-GitHub, Pull מוריד מ-GitHub.
  • מעלים פרויקט ל-GitHub פעם אחת, דרך Git ← Create Git Repository.
  • בכל מחשב חדש: Clone, ואחר כך Update-Database כדי ליצור את מסד הנתונים.
  • מתחילים לעבוד ב-Pull, ומסיימים ב-Commit ו-Push.
