יסודות JavaScript

איך גורמים לעמוד להגיב: לחיצות, הקלדה, הצגה והסתרה
💡 על מה העמוד הזה? HTML הוא השלד, CSS הבגדים, ו-JavaScript הוא מה שגורם לעמוד לזוז: כפתור שעושה משהו, הודעה שמופיעה, טופס שבודק את עצמו. JavaScript רץ בדפדפן, אחרי שהעמוד כבר הגיע מהשרת. איפה שמים אותו בפרויקט: מדריך 8, סעיף 4. חדשים בזה? התחילו ב-מה זה HTML, CSS ו-JavaScript?

✏️ איך עובדים עם העמוד: בכל עורך קוד אפשר לשנות את הקוד, והתוצאה מתעדכנת מיד בחלון הדפדפן שלידו. אם יש כמה קבצים (index.html, style.css, script.js), לחצו על השם שלהם כדי לעבור ביניהם. ↺ איפוס מחזיר את הדוגמה למצב ההתחלתי, ושני הכפתורים הקטנים לידו מסדרים את העורך והתוצאה זה ליד זה או אחד מעל השני. אי אפשר לשבור כלום, אז תתפרעו!

1. הצעד הראשון: לחיצה על כפתור

כמעט כל קוד JavaScript באתר עובד ככה: מוצאים אלמנט בעמוד, מחכים שמשהו יקרה לו (לחיצה), ואז משנים משהו.

שורהמה היא עושה
document.getElementById("myBtn")מוצא בעמוד את התגית עם id="myBtn".
addEventListener("click", function () { ... })"כשלוחצים, תריץ את מה שבסוגריים המסולסלים".
.textContent = "..."מחליף את הטקסט שבתוך התגית.
// ...הערה. JavaScript מתעלם ממנה.

2. console.log: הודעות למתכנת

alert מקפיץ הודעה למשתמש. אבל כשרוצים לבדוק מה קורה בקוד (מה הערך של משתנה, האם פונקציה רצה בכלל), כותבים הודעה לעצמנו, ב-Console. המשתמש לא רואה אותה.

📖 Consoleחלון בכלי המפתחים של הדפדפן (F12 ← לשונית Console), שמציג הודעות מהקוד ושגיאות. בעורכים בעמוד הזה, ההודעות מופיעות בחלון שחור מתחת לתוצאה.
פקודהאיך זה נראהמתי משתמשים
console.log("טקסט", x)שורה רגילה.הכי נפוץ: להדפיס ערך של משתנה, או לבדוק שהקוד הגיע לשורה מסוימת.
console.info(...)שורה עם סימן מידע (ℹ).מידע כללי. בפועל, כמעט כמו log.
console.warn(...)שורה צהובה עם ⚠.משהו חשוד, אבל לא שגיאה.
console.error(...)שורה אדומה עם ✖.משהו השתבש. (גם שגיאות אמיתיות של JavaScript מופיעות באדום.)
console.table(array)מערך או אובייקט כטבלה.לראות רשימה של אובייקטים בבת אחת.
console.clear()מנקה את החלון.כשיש יותר מדי הודעות.
💡 טריק הדיבאג הכי פשוט: כשמשהו לא עובד, שימו console.log בכמה מקומות בקוד. אם הודעה לא מופיעה, הקוד לא הגיע לשם. אם הערך שמודפס לא מה שציפיתם, מצאתם את הבעיה. (ב-C# יש לזה כלי חזק יותר: Breakpoints.)
⚠️ לפני שמסיימים: מחקו את ה-console.log-ים שהוספתם לבדיקה. הם לא מזיקים, אבל קוד נקי יותר נוח לקרוא.

3. משתנים

📖 משתנה"קופסה" עם שם, ששומרת ערך. ב-JavaScript מגדירים עם let (אפשר לשנות אחר כך) או const (קבוע).דוגמה: let count = 0; ואחר כך count = count + 1;. בשונה מ-C#, לא כותבים את הסוג (int, string).

4. מוצאים אלמנטים

פונקציהמה היא מחזירה
document.getElementById("x")האלמנט עם id="x".
document.querySelector(".card")האלמנט הראשון שמתאים לסלקטור CSS (כמו בעמוד ה-CSS).
document.querySelectorAll(".card")כל האלמנטים שמתאימים. עוברים עליהם עם forEach.

5. משנים עיצוב עם classList

אפשר לשנות עיצוב ישירות (element.style.color = "red"), אבל עדיף להגדיר class ב-CSS, ורק להוסיף או להוריד אותו ב-JavaScript:

פונקציהמה היא עושה
element.classList.add("x")מוסיפה את ה-class.
element.classList.remove("x")מורידה.
element.classList.toggle("x")אם יש, מורידה. אם אין, מוסיפה. מושלם לכפתורי "הפעל/כבה".

6. הצגה והסתרה

7. אירועים נוספים: הקלדה

חוץ מ-"click" יש עוד אירועים. "input" קורה בכל פעם שהמשתמש מקליד בשדה:

אירועמתי
clickלחיצה.
inputכל הקלדה בשדה.
changeשינוי של select או checkbox.
submitשליחת טופס.
mouseoverהעכבר נכנס לאלמנט.

8. רשימות ולולאות

מערך ([ ]) הוא רשימה. לולאה עוברת עליו ובונה HTML לכל פריט:

קודמה הוא עושה
tasks.push(x)מוסיף פריט לסוף המערך.
document.createElement("li")יוצר תגית חדשה (עוד לא בעמוד).
list.appendChild(li)מכניס אותה לעמוד, בסוף הרשימה.
function showTasks() { ... }פונקציה משלנו, שאפשר לקרוא לה כמה פעמים.

9. בדיקת טופס לפני שליחה

⚠️ חשוב: בדיקה ב-JavaScript היא רק לנוחות. משתמש יכול לעקוף אותה, ולכן תמיד בודקים גם בשרת. בפרויקט, ASP.NET עושה את שתי הבדיקות בשבילכם (מדריך 12).

10. חלונות קופצים

פונקציהמה היא עושה
alert("טקסט")הודעה עם כפתור "אישור".
confirm("בטוחים?")שאלה עם "אישור" ו"ביטול". מחזירה true או false.
prompt("איך קוראים לך?")שאלה עם תיבת טקסט. מחזירה את מה שהמשתמש הקליד (או null אם ביטל).
💡 מתי להשתמש בהם? הם נוחים לבדיקות ולדברים קטנים (כמו "בטוחים שרוצים למחוק?"). באתר מעוצב עדיף להציג הודעות בתוך העמוד, או בחלון קופץ של Bootstrap (בספריית קטעי הקוד: "חלון קופץ").
💡 בפרויקט: חלון אישור לפני מחיקה, בשורה אחת: בספריית קטעי הקוד, "חלון אישור לפני מחיקה". ו-JavaScript שמדבר עם השרת בלי לטעון את העמוד: מתקדם ד.

11. כשמשהו לא עובד

ב-JavaScript, שגיאה אחת עוצרת את כל הקוד שאחריה, ובדרך כלל לא רואים אותה בעמוד. איפה מוצאים אותה:

  • בעמוד הזה: שגיאה תופיע בפס אדום מתחת לתוצאה. נסו לכתוב בדוגמה getElementByid (עם d קטנה).
  • באתר שלכם: F12 ← Console. השגיאה מופיעה שם באדום, עם הקובץ ומספר השורה.
  • אין שגיאה, אבל זה לא עובד? הוסיפו console.log (סעיף 2) כדי לראות עד איפה הקוד מגיע ומה הערכים.
שגיאה נפוצההסיבה
Cannot read properties of nullה-id בקוד לא זהה ל-id בתגית, או שהסקריפט רץ לפני שהתגית קיימת.
... is not a functionטעות כתיב בשם פונקציה. JavaScript רגיש לאותיות גדולות: getElementById ולא getElementByid.
... is not definedמשתנה שלא הוגדר, או טעות כתיב בשם שלו.

📌 מה למדנו

  • מוצאים אלמנט (getElementById / querySelector), מחכים לאירוע (addEventListener), ומשנים משהו (textContent, classList).
  • console.log (וגם warn, error, table) כותב הודעות לעצמכם ב-Console. alert, confirm ו-prompt מדברים עם המשתמש.
  • משתנים עם let ו-const. מערכים עם [ ], ו-forEach עובר עליהם.
  • hidden מסתיר, classList.toggle מחליף עיצוב.
  • בדיקה ב-JavaScript היא לנוחות. הבדיקה האמיתית בשרת.
  • שגיאות רואים ב-F12 ← Console.
