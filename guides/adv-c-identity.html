מתקדם ג: התאמת ההרשמה

שדה "שם מלא" למשתמש, ודפי הרשמה והתחברות בעברית
💡 על מה המדריך הזה? מערכת המשתמשים שקיבלנו מוכנה שומרת רק אימייל וסיסמה, והדפים שלה באנגלית. כאן נוסיף למשתמש שדה משלנו (שם מלא), נבקש אותו בהרשמה, ונתרגם את הדפים.

מה צריך לפני: פרויקט עם Individual Accounts (מדריך 1), והיכרות עם Migrations (מדריך 13) ועם Scaffolding (מדריך 15). אם עשיתם את מדריך 17, יש שם קוד שגם אותו נעדכן.
⚠️ לפני שמתחילים: Commit! המדריך הזה משנה קבצים בכמה מקומות. עשו Commit (מדריך 3) עכשיו, כדי שאם משהו ישתבש, תוכלו לחזור.

1. מחלקת משתמש משלנו

📖 מושג: ירושה (Inheritance) מחלקה שמקבלת את כל מה שיש במחלקה אחרת, ומוסיפה משהו משלה. נכתב עם נקודתיים: class ApplicationUser : IdentityUser. דוגמה: IdentityUser כבר כולל אימייל, סיסמה ועוד. ApplicationUser יקבל את כל אלה, ועוד שדה אחד: שם מלא. (ראינו את זה כבר: HomeController : Controller.)

קליק ימני על Models ← Add ← Class ← ApplicationUser.cs. החליפו את כל התוכן ב:

using Microsoft.AspNetCore.Identity;

namespace MyProject.Models
{
    public class ApplicationUser : IdentityUser
    {
        public string FullName { get; set; } = "";
    }
}

שנו את MyProject לשם הפרויקט שלכם (כמו שכתוב בשורת ה-namespace בקבצים האחרים).

2. מחליפים IdentityUser ב-ApplicationUser

עכשיו צריך להגיד לכל האתר להשתמש במחלקה החדשה. זה בארבעה מקומות:

  • Data/ApplicationDbContext.cs: בשורה של המחלקה, הוסיפו <ApplicationUser> מיד אחרי IdentityDbContext: 
    public class ApplicationDbContext(DbContextOptions<ApplicationDbContext> options) : IdentityDbContext<ApplicationUser>(options)
    (כל מה שבתוך המחלקה, כמו ה-DbSet-ים, נשאר כמו שהוא. אם ApplicationUser באדום, Ctrl+..)
  • Program.cs: בשורה של AddDefaultIdentity, החליפו IdentityUser ב-ApplicationUser: 
    builder.Services.AddDefaultIdentity<ApplicationUser>(options => options.SignIn.RequireConfirmedAccount = true)
    (אם יש בראש הקובץ קו אדום על ApplicationUser, Ctrl+..)
  • Views/Shared/_LoginPartial.cshtml: בשתי השורות הראשונות (@inject), החליפו IdentityUser ב-ApplicationUser: 
    @inject SignInManager<ApplicationUser> SignInManager
@inject UserManager<ApplicationUser> UserManager
  • בכל מקום אחר: חפשו בכל הפרויקט (Ctrl+Shift+F) את המילה IdentityUser. אם עשיתם את מדריך 17, היא תופיע גם בקוד שיוצר את המנהל הראשון ב-Program.cs (UserManager<IdentityUser>). החליפו בכל מקום ל-ApplicationUser, חוץ מהשורה : IdentityUser בקובץ ApplicationUser.cs עצמו.

3. Migration

עשו Build (Ctrl+Shift+B) וודאו שאין שגיאות. אחר כך, עם האתר עצור, ב-Package Manager Console:

Add-Migration AddUserFullName
Update-Database
ב-SQL Server Object Explorer, לטבלה dbo.AspNetUsers נוספה עמודה FullName.

4. מוציאים את דפי ההרשמה לעריכה

דפי ההרשמה וההתחברות "מוסתרים" בתוך ספרייה. כדי לשנות אותם, צריך ליצור עותק שלהם בפרויקט, עם Scaffolding:

  • עצרו את האתר. ב-Solution Explorer, קליק ימני על שם הפרויקט ← Add ← New Scaffolded Item.
  • בצד בחרו Identity, ובמרכז שוב Identity. לחצו Add (ייתכן שתצטרכו לחכות להתקנת חבילות).
  • בחלון שנפתח, סמנו רק את Account\Register ואת Account\Login.
  • ב-DbContext class בחרו ApplicationDbContext, ולחצו Add.
כאן תבוא תמונה של חלון Add Identity עם Register ו-Login מסומנים
נוצרה התיקייה Areas/Identity/Pages/Account, ובה Register.cshtml ו-Login.cshtml. לכל אחד מהם יש גם קובץ .cshtml.cs (לחצו על החץ שלידו ב-Solution Explorer).
📖 מה זה .cshtml.cs? דפי Identity בנויים בשיטה קצת אחרת, שנקראת Razor Pages: במקום Controller נפרד, לכל עמוד יש קובץ קוד צמוד (.cshtml.cs). התפקיד שלו דומה ל-Controller: הוא מטפל בטופס.

5. שדה "שם מלא" בהרשמה

בקוד (Register.cshtml.cs)

  • חפשו בקובץ את public class InputModel. בתוכו, לפני ה-Email, הוסיפו: 
    [Required(ErrorMessage = "נא להזין שם מלא")]
[Display(Name = "שם מלא")]
public string FullName { get; set; } = "";
  • חפשו את השורה var user = CreateUser();. מיד אחריה הוסיפו: 
    user.FullName = Input.FullName;

בעמוד (Register.cshtml)

חפשו את הבלוק של שדה האימייל (מתחיל ב-<div class="form-floating mb-3"> ובתוכו Input.Email). לפניו הדביקו:

<div class="form-floating mb-3">
    <input asp-for="Input.FullName" class="form-control" autocomplete="name" aria-required="true" placeholder="שם מלא" />
    <label asp-for="Input.FullName"></label>
    <span asp-validation-for="Input.FullName" class="text-danger"></span>
</div>
בעמוד ההרשמה יש שדה "שם מלא". הירשמו עם משתמש חדש, ובדקו ב-View Data של dbo.AspNetUsers שהשם נשמר בעמודה FullName.

6. תרגום לעברית

עכשיו, כשהדפים בפרויקט שלכם, אפשר לתרגם הכול:

  • טקסטים בעמוד (Register.cshtml, Login.cshtml): כותרות כמו Create a new account., טקסט הכפתורים, וקישורים כמו Forgot your password?.
  • שמות השדות והודעות השגיאה (בקבצי ה-.cshtml.cs, בתוך InputModel): ל-[Display(Name = "Email")] שנו ל-"אימייל", ולכל [Required] הוסיפו ErrorMessage בעברית (כמו במדריך 12).
⚠️ הודעות על הסיסמה (למשל "Passwords must have at least one uppercase") מגיעות מ-Identity עצמו, ולא מהקבצים האלה. לתרגם אותן זה מורכב יותר, ואפשר לוותר על זה.

7. "שלום, [שם מלא]" בתפריט

ב-_LoginPartial.cshtml, חפשו את הקישור שבו כתוב Hello @User.Identity?.Name!. החליפו את הטקסט הזה ב:

שלום, @((await UserManager.GetUserAsync(User))?.FullName)!

UserManager.GetUserAsync(User) מביא את המשתמש המחובר ממסד הנתונים, כ-ApplicationUser, ומשם לוקחים את FullName.

אחרי התחברות, בתפריט כתוב "שלום" עם השם המלא. (למשתמשים שנרשמו לפני השינוי אין שם, ולכן יופיע רק "שלום, !".)

🔧 אם זה לא עובד

  • "No service for type UserManager<IdentityUser>" (או SignInManager): נשאר IdentityUser במקום כלשהו. חפשו שוב בכל הפרויקט (סעיף 2).
  • Scaffolding של Identity נכשל: עשו Build ותקנו את כל השגיאות, ודאו שהאתר עצור, ונסו שוב.
  • ב-Register.cshtml.cs, user.FullName מסומן באדום: הפונקציה CreateUser בקובץ מחזירה IdentityUser. החליפו בה (ובשורות סביבה) את IdentityUser ב-ApplicationUser.
  • הכול נשבר ולא ברור למה: בשביל זה עשינו Commit בהתחלה. ב-Git Changes אפשר לבטל את השינויים ולהתחיל מחדש.

✏️ תרגיל

  1. הוסיפו למשתמש גם שדה "כיתה" (public string? ClassName { get; set; }), עם Migration, שדה בהרשמה, והצגה בתפריט.
  2. תרגמו לעברית את כל הטקסטים ושמות השדות בעמוד ההתחברות.

📌 מה למדנו

  • מוסיפים שדות למשתמש עם מחלקה שיורשת מ-IdentityUser, ומחליפים אותה בכל הפרויקט.
  • כדי לערוך את דפי ההרשמה וההתחברות, יוצרים להם עותק עם Scaffolding של Identity.
  • שדה חדש בהרשמה: ב-InputModel, ב-OnPostAsync ובעמוד עצמו.
  • UserManager.GetUserAsync(User) מביא את המשתמש המחובר עם כל השדות שלו.
