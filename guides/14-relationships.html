מדריך 14: קשרים בין טבלאות

קטגוריה עם הרבה מוצרים: איך מחברים טבלה אחת לאחרת
💡 על מה המדריך הזה? בכמעט כל אתר, המידע מחובר: למוצר יש קטגוריה, להזמנה יש משתמש, לתגובה יש פוסט. במדריך הזה נוסיף קטגוריות, נחבר כל מוצר לקטגוריה, ונבחר קטגוריה מרשימה נפתחת בטופס.

מה צריך לפני: מדריך 13 (מסד נתונים) הוא תנאי מקדים: צריך טבלת Products במסד הנתונים, ו-ProductsController שעובד איתה.

1. מה זה קשר "אחד לרבים"?

📖 מושג: קשר אחד לרבים (One-to-Many) לכל קטגוריה יכולים להיות הרבה מוצרים, אבל לכל מוצר יש קטגוריה אחת. דוגמאות נוספות: לכיתה הרבה תלמידים, ולכל תלמיד כיתה אחת. למשתמש הרבה הזמנות, ולכל הזמנה משתמש אחד.
📖 מושג: מפתח זר (Foreign Key) עמודה בטבלה אחת ששומרת את ה-Id של שורה בטבלה אחרת. ככה מחברים ביניהן. דוגמה: בטבלת המוצרים תהיה עמודה CategoryId. אם במוצר "עט" כתוב שם 2, פירוש הדבר שהעט שייך לקטגוריה שה-Id שלה 2 (למשל "ציוד כתיבה").

2. המודלים

מודל חדש: Category

קליק ימני על Models ← Add ← Class ← Category.cs. בראש הקובץ הוסיפו using System.ComponentModel.DataAnnotations;, ובתוך המחלקה הדביקו:

public int Id { get; set; }

[Required(ErrorMessage = "נא להזין שם קטגוריה")]
[Display(Name = "קטגוריה")]
public string Name { get; set; } = "";

public List<Product> Products { get; set; } = new List<Product>();

השורה האחרונה היא הצד של ה"רבים": לכל קטגוריה יש רשימה של מוצרים.

שינוי ב-Product

ב-Models/Product.cs, הוסיפו בתוך המחלקה (ואם בראש הקובץ אין using System.ComponentModel.DataAnnotations;, הוסיפו גם אותו):

[Display(Name = "קטגוריה")]
public int? CategoryId { get; set; }

public Category? Category { get; set; }
שורההסבר
int? CategoryIdהמפתח הזר: ה-Id של הקטגוריה. ה-? אומר שמותר שלמוצר לא תהיה קטגוריה. זה חשוב, כי למוצרים שכבר קיימים במסד הנתונים עוד אין קטגוריה.
Category? Categoryהקטגוריה עצמה, כאובייקט שלם. בזכותה אפשר לכתוב product.Category.Name ולקבל את שם הקטגוריה.
💡 השמות חשובים: בזכות השם CategoryId (שם ה-Property Category ועוד Id), Entity Framework מבין לבד שזה מפתח זר לטבלת הקטגוריות.

מוסיפים כמה קטגוריות

עוד אין לנו עמוד להוספת קטגוריות (במדריך 15 ניצור אחד בלחיצת כפתור), אז נוסיף אותן ישירות בטבלה:

  • ב-SQL Server Object Explorer, קליק ימני על dbo.Categories ← View Data.
  • בשורה הריקה בתחתית, הקלידו שם קטגוריה בעמודה Name (את Id משאירים ריק, הוא יתמלא לבד) ולחצו Enter.
  • הוסיפו כך 2-3 קטגוריות.

4. רשימה נפתחת בטופס

כדי לבחור קטגוריה בטופס, ה-Controller צריך לשלוח לו את רשימת הקטגוריות. ב-ProductsController, שנו את שני ה-Create:

public IActionResult Create()
{
    ViewBag.Categories = new SelectList(_context.Categories.ToList(), "Id", "Name");
    return View();
}

[HttpPost]
[ValidateAntiForgeryToken]
public IActionResult Create(Product product)
{
    if (!ModelState.IsValid)
    {
        ViewBag.Categories = new SelectList(_context.Categories.ToList(), "Id", "Name");
        return View(product);
    }

    _context.Products.Add(product);
    _context.SaveChanges();
    return RedirectToAction("Index");
}

SelectList יסומן באדום. Ctrl+. יוסיף using Microsoft.AspNetCore.Mvc.Rendering;.

📖 מושג: ViewBag "שקית" שאפשר לשים בה מידע נוסף בשביל ה-View, חוץ מה-Model. ה-Model כאן הוא המוצר, ואת רשימת הקטגוריות שמים ב-ViewBag.
📖 מושג: SelectList רשימה מוכנה בשביל <select>. "Id" הוא הערך שנשמר כשבוחרים, ו-"Name" הוא הטקסט שהמשתמש רואה.
⚠️ למה פעמיים? אם הטופס לא תקין, מחזירים אותו שוב, וגם אז צריך את רשימת הקטגוריות. אם תשכחו את השורה ב-POST, הרשימה הנפתחת תהיה ריקה אחרי שגיאה.

ב-Views/Products/Create.cshtml, הוסיפו בתוך הטופס, לפני כפתור השמירה:

<div class="mb-3">
    <label asp-for="CategoryId" class="form-label"></label>
    <select asp-for="CategoryId" asp-items="ViewBag.Categories" class="form-select">
        <option value="">-- בחרו קטגוריה --</option>
    </select>
</div>
בטופס הוספת מוצר יש רשימה נפתחת עם הקטגוריות שהוספתם. הוסיפו מוצר עם קטגוריה, ובדקו ב-View Data של dbo.Products שבעמודה CategoryId נשמר המספר הנכון.

5. מציגים את שם הקטגוריה ברשימה

כברירת מחדל, כשמביאים מוצרים, Entity Framework לא מביא איתם את הקטגוריה (כדי לחסוך). צריך לבקש את זה במפורש עם Include. ב-Index של ProductsController, שנו את השורה הראשונה:

var products = _context.Products.Include(p => p.Category).ToList();

(אם Include באדום: Ctrl+. יוסיף using Microsoft.EntityFrameworkCore;.)

📖 מה זה p => p.Category? דרך קצרה לכתוב "לכל מוצר p, קח את ה-Category שלו". כאן היא אומרת ל-Include מה להביא יחד עם המוצרים.

ב-Views/Products/Index.cshtml, הוסיפו עמודה לטבלה. בשורת הכותרות <th>קטגוריה</th>, ובתוך הלולאה:

<td>@product.Category?.Name</td>
📖 למה ?. ולא סתם נקודה? ?. אומר "אם יש קטגוריה, קח את השם שלה. אם אין, אל תעשה כלום". למוצרים בלי קטגוריה, נקודה רגילה הייתה גורמת לשגיאה (NullReferenceException).
ברשימת המוצרים יש עמודת קטגוריה. למוצרים הישנים (בלי קטגוריה) היא ריקה.

6. הכיוון השני: כל המוצרים בקטגוריה

אפשר גם להתחיל מקטגוריה ולקבל את כל המוצרים שלה. הוסיפו ל-ProductsController:

public IActionResult ByCategory(int id)
{
    var category = _context.Categories
        .Include(c => c.Products)
        .FirstOrDefault(c => c.Id == id);

    if (category == null)
    {
        return NotFound();
    }
    return View(category);
}

וצרו לו View (קליק ימני ← Add View ← Razor View - Empty ← ByCategory.cshtml):

@model Category
@{
    ViewData["Title"] = Model.Name;
}

<h1>@Model.Name</h1>

@if (Model.Products.Count == 0)
{
    <p>אין עדיין מוצרים בקטגוריה הזאת.</p>
}

<ul>
    @foreach (var product in Model.Products)
    {
        <li>@product.Name: @product.Price ₪</li>
    }
</ul>
היכנסו ל-/Products/ByCategory/1. מופיעים כל המוצרים של הקטגוריה הראשונה.

🔧 אם זה לא עובד

  • Update-Database נכשל עם שגיאה על FOREIGN KEY: כנראה כתבתם int CategoryId בלי סימן שאלה. המוצרים הקיימים לא יכולים לקבל קטגוריה שלא קיימת. הוסיפו ?, ואז הריצו Remove-Migration, ושוב Add-Migration ו-Update-Database.
  • הרשימה הנפתחת ריקה: אין קטגוריות בטבלה (סעיף 3), או ששכחתם את שורת ה-ViewBag ב-Action.
  • עמודת הקטגוריה תמיד ריקה, גם למוצרים חדשים: חסר .Include(p => p.Category) ב-Index.
  • NullReferenceException בעמוד הרשימה: כתבתם product.Category.Name במקום product.Category?.Name.

✏️ תרגיל

  1. בעמוד הפרטים של מוצר (Details), הציגו גם את שם הקטגוריה. (רמז: גם שם צריך Include, ובמקום Find משתמשים ב-FirstOrDefault(p => p.Id == id).)
  2. הפכו את שם הקטגוריה ברשימת המוצרים לקישור לעמוד ByCategory שלה.
  3. בונוס: צרו קשר משלכם. למשל, מודל Review (ביקורת) עם טקסט וציון, כשלכל מוצר יש הרבה ביקורות.

📌 מה למדנו

  • קשר אחד לרבים: במודל של ה"אחד" יש רשימה (List<Product>), ובמודל של ה"רבים" יש מפתח זר (CategoryId) ואובייקט (Category).
  • int? מאפשר מוצר בלי קטגוריה, וזה מונע שגיאות עם נתונים שכבר קיימים.
  • רשימה נפתחת: SelectList ב-ViewBag, ו-<select asp-for asp-items> בטופס.
  • כדי לקבל גם את המידע המחובר צריך Include, ומציגים עם ?..
